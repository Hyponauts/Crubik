# Crubik

[![codecov](https://codecov.io/gh/Hyponauts/Crubik/graph/badge.svg?token=OUWHSOUDOH)](https://codecov.io/gh/Hyponauts/Crubik)

Crubik is an offline-first Flutter companion for Bluetooth smart cubes. The MVP keeps the complete practice loop on-device: connect a cube, follow a scramble, watch turns update a live 3x3 model, time the solve, and retain the session without an account or network connection.

## MVP capabilities

- Responsive phone, tablet, and desktop practice layouts.
- Smart-cube protocol adapters for the packet-tested families documented in [Crubik cube device compatibility](docs/cube-device-compatibility.md).
- MAC-salted AES packet decryption, initial facelet-state synchronization, and move-history recovery for supported protocols.
- A pure-Dart 54-sticker cube model, notation parser, and 20-move practice scramble generator.
- Touch and spacebar timing, move capture, automatic stop on a solved cube, best/mean/Ao5 statistics, and recent-solve deletion.
- Durable local solve storage through SQLite on native platforms and Drift's IndexedDB-backed storage on the web.
- Versioned JSON solve-history export through the clipboard.
- A hardware-free demo/manual-input path.

The current scramble generator is deliberately labelled a **practice scramble**. A production WCA random-state generator remains a follow-up; its pure-Dart implementation should be validated against TNoodle and cubing.js.

The current history schema exports solve summaries and timing/input metadata; versioned persistence and export of the raw per-move event stream remains future work. Do not describe the current JSON as a lossless raw-event export.

## Cube device compatibility

Current protocol coverage, compatibility evidence, physical-device compatibility validation, and release support status are maintained in [Crubik cube device compatibility](docs/cube-device-compatibility.md). Packet-tested adapters must not be described as supported for release without the required real-hardware evidence.

## Run and verify

```sh
flutter pub get
dart run build_runner build
flutter run
flutter analyze
flutter test
```

Generated Drift Dart source and the web database runtime files are intentionally
excluded from Git. Generate them after dependency setup, whenever database
tables, migrations, DAOs, or the worker entrypoint change, and whenever locked
web database dependencies change:

```sh
dart run build_runner build
```

For active schema or worker work, `dart run build_runner watch` keeps the local
generated outputs current. A clean build needs network access to download the
pinned sqlite3 WebAssembly release asset; incremental builds reuse the verified
local output.

The web build loads two version-matched runtime payloads directly:

- `web/drift_worker.dart.js` is generated by `build_runner` from
  `web/drift_worker_entrypoint.dart` with dart2js `-O4`. It must exist before
  running Flutter's web tooling and is not committed.
- `web/sqlite3.wasm` is downloaded by `build_runner` from the upstream release
  matching the locked `sqlite3` package (`2.9.4`). Its SHA-256 checksum is
  `922a76b182b6af69b030c8e2fdd3283ecc8e827248b20e4b1f3f3db170b52117`.

When Drift changes, regenerate the worker. When sqlite3 changes, update
`tool/sqlite3_wasm_asset.json` with the matching release URL and checksum. In
both cases, build the web app and test database startup in a browser. Neither
generated runtime file should be committed.

## CI/CD

GitHub Actions workflows automatically validate, build, and deploy Crubik:

- **CI Pipeline**: Every pull request and push runs quality checks (format, analyze, test) and builds all supported platforms (Web, Android, Windows, macOS, Linux).
- **Web Deployment**: Pushes to `main` and version tags automatically deploy to GitHub Pages.
- **Release Automation**: Pushing a version tag (e.g., `v1.0.0`) creates a GitHub Release with downloadable artifacts for all platforms.
- **Artifacts**: Build outputs are available for download from the Actions tab for 30 days.

See [`.github/workflows/README.md`](.github/workflows/README.md) for complete CI/CD documentation, setup instructions, and troubleshooting.
